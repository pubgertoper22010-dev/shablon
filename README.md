# Обзвон · шаблон набора администрации

Сайт с закрытым доступом: пока сотрудник не вошёл по выданному ID, показывается только
экран входа — без вопросов. После входа открывается скрипт обзвона (32 вопроса с
эталонными ответами), чек-лист проверки кандидата, карточка кандидата и генератор отчёта.

Управление доступом — из панели владельца прямо в сайте: вы пишете ID сотрудников,
настраиваете роли и включаете/выключаете профили.

## Как открыть

- **Локально:** двойной клик по `Шаблон обзвона.html` (или `index.html`) — работает офлайн.
- **Локальный сервер** (доступ с телефона в одной сети):
  ```bash
  python -m http.server 8099
  ```
  затем `http://127.0.0.1:8099/`.
- **Публикация:** загрузите папку на GitHub Pages / Netlify / Vercel — статика, бэкенд не нужен.

## Структура

```
Шаблон обзвона.html       — автономная версия: весь CSS и JS внутри одного файла
index.html                — то же самое, но отдельными файлами (удобно править)
assets/css/styles.css     — оформление, тёмная и светлая темы, стиль для печати
assets/js/app.js          — скрипт-вопросы + логика доступа, профилей, отчётов
```

## Как выдать доступ (1 раз)

1. Откройте сайт → экран входа → **«Вход для владельца»**.
2. Придумайте **пароль владельца** и укажите **свой ID** (после этого вы сможете входить и по ID, без пароля).
3. В панели владельца:
   - **«Выдать доступ»** — добавить одного сотрудника: ID, отображаемое имя, роль.
   - **«Массовое добавление»** — вставить сразу несколько ID (каждый с новой строки или через запятую).
   - Таблица профилей: переименовать, сменить роль, включить/выключить доступ, удалить, видно число входов и последний вход.
   - **«Экспорт базы» / «Импорт базы»** — перенести список ID на другой компьютер или в другой браузер.

Сотрудник заходит на сайт, вводит выданный ID — и сразу получает доступ к скрипту.
Галочка «Не выходить из аккаунта» запоминает вход; без неё сессия живёт до закрытия вкладки.

## Что умеет

| Блок | Возможности |
| --- | --- |
| Экран входа | Вход по ID, сообщения об отказе (нет ID / профиль отключён), вход владельца по паролю |
| Шаг 1 · Открытие | Приветствие и 4 вводных вопроса, карточка кандидата (ник, возраст, часовой пояс с автоопределением, время на проект, контакт, опыт) |
| Шаг 2 · Скрипт | 32 вопроса в 3 разделах; эталонный ответ скрыт и открывается по кнопке; копирование ответа; отметка «вопрос проверен»; поиск (`/`); прогресс-бар; показ/скрытие всех ответов |
| Шаг 3 · Отчёт | Вердикт (принят / на доработку / отказ), сводка, список непроверенных вопросов, копирование отчёта и выгрузка в `.txt` |
| Профиль | Свой профиль: сменить отображаемое имя, посмотреть роль и историю входов, выйти |

Дополнительно: тёмная/светлая тема, печать в PDF (ответы в печати раскрыты),
автосохранение анкеты, отметок и заметок — **отдельно для каждого профиля**
(у сотрудника свои данные, у другого — свои).

## Как отредактировать вопросы

Все тексты лежат в одном месте — `assets/js/app.js`, массив `SCRIPT`:

```js
{
  q: "Что даётся за ДМ?",                     // вопрос
  a: "Наказание — <strong>60 минут деморгана</strong>.",  // эталонный ответ (можно HTML)
  note: "Дополнительное примечание (необязательно).",
  tags: ["деморган"]                          // метки для поиска
}
```

Разделы задаются объектами с полями `title`, `subtitle` и `items`. После правки
обновите страницу — нумерация и счётчики пересчитаются автоматически.
В автономном файле `Шаблон обзвона.html` то же самое правится внутри `<script>` в конце страницы.

## Важно про безопасность

Пароль владельца не хранится в открытом виде — только SHA-256 с солью и 2000 итераций.
Но сайт статический: база профилей и все анкеты лежат в `localStorage` **того браузера**,
где вы их создали.

- Для внутреннего пользования (своя команда, один браузер) этого достаточно.
- Если нужен реальный барьер между людьми — нужен сервер (или хотя бы хранение списка ID
  в общем файле/хостинге). Любой, кто откроет исходный код страницы, увидит текст вопросов
  и список ID — это ограничение клиентского подхода, а не дыра в реализации.
- «Экспорт/Импорт базы» нужен именно для переноса доступа между устройствами.

## Прочее

- Нумерация в скрипте сквозная и приведена в порядок: в исходном шаблоне вопрос 28
  встречался дважды, здесь он разведён на 28 и 29 (всего 32 вопроса).
- Формулировки наказаний стоит сверять с актуальной версией правил проекта перед обзвоном.
